# CanyonGlow v1.0

**RGB Control for NUC 11 & 12 Extreme**

A graphical interface for control of the four RGB LED zones on the
Intel NUC 11 Extreme (Beast Canyon) and NUC 12 Extreme (Dragon Canyon).
Communication is handled directly via the serial interface of the embedded controller.

**[Download & installation](#installation-and-startup-windows)**

---

## Supported Hardware

| Model | Codename | Typical Kit IDs |
|---|---|---|
| Intel NUC 11 Extreme | Beast Canyon | NUC11BTMi7, NUC11BTMi9 |
| Intel NUC 12 Extreme | Dragon Canyon | NUC12DCMi7, NUC12DCMi9 |

Support is limited to these two model families. Other NUC models
(such as NUC Mini, NUC Pro or NUC 13+) are not supported.

**Hardware testing:** CanyonGlow has been tested only on a **NUC 11 Extreme**.
Support for the **NUC 12 Extreme has not yet been verified on hardware**.

---

## RGB Zones

The device has four independently controllable zones:

| Zone | Position |
|---|---|
| **Skull** | Skull logo (front) |
| **Bottom Left** | Underside left |
| **Bottom Right** | Underside right |
| **Bottom Front** | Underside front |

## Features

### Effects
Each zone supports the following effects independently:

- **Solid** — static colour
- **Pulse** — soft fade in and out
- **Breathing** — smooth continuous fade
- **Strobe** — flash effect ⚠️
- **Rainbow** — automatic colour cycle
- **PT1 / PT2 / PT3** — PulseTrain: three-colour sequence palette shared by all
  PTx zones. Colours are configured in the "PulseTrain Palette" panel.
  **Send Palette** sends the shared palette and the selected PTx zone's settings
  to the controller.

> ⚠️ **Pulse and Strobe** send different commands to the controller (`P2` vs. `P4`),
> but may look similar on the device. The effects are generated by the controller.

### Colour & Brightness

- Colour bar with 256 hue values (HSV model)
- Snaps to standard colours (Red, Orange, Yellow, Green, Cyan, Blue, Purple, Pink)
- **Shift + drag** on the colour bar disables snapping for free colour selection
- Direct numeric entry in the spinbox field (0–255)
- Brightness in 6 levels (0–5), globally and per zone
- Brightness and speed are adjusted on the right for the selected zone.
  Speed (0–5) is active only for animated effects. Rainbow chooses colours
  automatically; PulseTrain uses the shared palette.

### Zone Sync

- **SYNC** mirrors changes to the hue value between linked zones in the interface.
  It does not link effects, brightness or speed.
- Changed values are applied only when sent. **Send All** transfers them together;
  **send** in a row transfers only that zone.
- **Copy to All Zones** copies the selected zone's settings into all other rows,
  also without sending immediately.

### Global Controls

- **ALL ZONES ON / ALL ZONES OFF** — shows the next action and switches global
  lighting on or off immediately. While off, zone controls and global brightness
  are locked; profiles, the log, language and theme selection remain available.
- **Global Brightness** — brightness slider applies to all zones on send
- **Send All** — transfers all zones and the shared palette with one click

### Profiles

- Save and load configurations as `.json` files
- Profile name freely selectable
- Example profile: `example_default_green_profile.json`
- Loading initially changes only the interface. Apply the loaded zone settings
  with **Send All** once the controller has been detected and global lighting is
  switched on. SYNC links are not saved.

### Interface

- **Dark Mode / Light Mode** toggle
- **German / English** language toggle
- On first launch, the tool uses English and Dark Mode. The last selected language
  and light/dark mode are saved automatically and restored on the next launch.
  Brief tooltips follow the selected language.
- Log showing sent commands, status messages and queried controller responses
- Save and clear the log; translatable application messages follow the selected
  language, including existing entries. Raw data remains unchanged.

## Installation and startup (Windows)

The release packages are intended for **Windows 10/11 (x64)**. Python and Python
packages are bundled and do not need to be installed separately.
Intel NUC Software Studio is not required.

> **Hardware testing:** Tested only on a NUC 11 Extreme; NUC 12 Extreme is untested.
>
> **Use at your own risk.** To the extent permitted by applicable law, CanyonGlow
> is provided without warranty and its authors are not liable for damage arising
> from its use, including incorrect parameters or settings. See the [MIT license](LICENSE).

For a new installation, setup defaults to English; German remains selectable.
When updating, setup retains the previously used installation language.

- **[Download installer (.exe)](https://github.com/rattensuppe/CanyonGlow/releases/download/v1.0/CanyonGlow-v1.0-Setup-x64.exe):**
  recommended for most users. Run `CanyonGlow-v1.0-Setup-x64.exe`. Installation is per user, with
  a Start Menu shortcut and an optional desktop shortcut.
- **[Download portable ZIP](https://github.com/rattensuppe/CanyonGlow/releases/download/v1.0/CanyonGlow-v1.0-Portable-x64.zip):**
  no installation needed. Fully extract `CanyonGlow-v1.0-Portable-x64.zip` and run
  `CanyonGlow.exe` inside the `CanyonGlow` folder. Keep the whole folder together,
  including `_internal`; the EXE alone is not sufficient.

[Checksums (SHA-256)](https://github.com/rattensuppe/CanyonGlow/releases/download/v1.0/CanyonGlow-v1.0-SHA256SUMS.txt)
· [Release notes](https://github.com/rattensuppe/CanyonGlow/releases/tag/v1.0)

The serial device driver must be installed. Instructions for Windows Update and
the official Prolific download are in [drivers/README_EN.txt](drivers/README_EN.txt).

On startup, the tool searches for the Prolific/PL2303 controller and reads its
status. After successful detection, zone settings are read from the device.
Sending is available while global lighting is switched on.
Without a detected controller, profiles can be prepared,
saved and loaded; sending is disabled.

**Scan Ports** refreshes the port list. Select a port at the top right or enter
one manually. **Check Device** queries the controller ID and logs the result;
it does not replace automatic status detection at startup. Restart the tool
after installing a driver or resolving connection problems.

Colour, effect, brightness, speed and individual zone ON/OFF switches initially
change only the interface. Use **send**, **Send All** or **Send Palette** to apply
them. The global ON/OFF button and **Factory Reset** act on the controller immediately.

## Updating and uninstalling

To update, run the new setup. The existing installation folder is reused;
previous application shortcuts are replaced with CanyonGlow shortcuts during
the rename. Start Menu and desktop shortcuts use the Documents folder as
their working directory.

Uninstall a setup installation through Apps in Windows Settings. Additional
profile files are not deleted. The portable version does not require
installation or uninstallation.

The packages are currently unsigned.

Language and appearance are saved per Windows user in
`%LOCALAPPDATA%\CanyonGlow\settings.json`. Setup and portable versions use the same
file. These settings are retained across updates.

## Profile Format

Profiles are saved as UTF-8 encoded JSON:

```json
{
  "name": "My Profile",
  "all_enabled": true,
  "pulse_train_hues": [0, 96, 160],
  "zones": {
    "Skull": {
      "enabled": true,
      "pattern": "Solid",
      "brightness": 5,
      "frequency": 0,
      "custom_hue": 96
    }
  }
}
```

Effects in the interface: `Solid`, `Pulse`, `Breathing`, `Strobe`, `PT1`, `PT2`, `PT3`, `Rainbow`  
Hue range: `0–255` · Brightness: `0–5` · Speed: `0–5`

The example shows only one zone. Saving writes all four zones; missing zones are
filled with defaults when loading. The off state is stored using `enabled`.
Existing JSON profiles remain usable.

## Serial Communication

The controller communicates via a virtual COM port (USB).  
The operating system assigns the actual port number, which may differ from
`COM3`. `COM3` is only a fallback value when no ports are detected.

Each time the port is opened, the software waits **2 seconds** before the first
command. Individual commands are spaced **0.1 seconds** apart. Sending can
therefore take a moment; additional send operations are processed sequentially.
